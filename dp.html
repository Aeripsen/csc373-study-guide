Why this question is the most forgiving on the paper

The parts are marked separately and the exam says "the subquestions are not independent", which cuts both ways: a wrong array in (a) is not re-punished in (b) and (c) as long as your recurrence is consistent with what you wrote. So even a partly wrong idea carries marks through, provided you keep using your own definition.

The one thing that destroys the question is changing your mind halfway and having (b) refer to an array that (a) did not define. Pick a definition, write it down, and stick to it.

Part (a): defining the array

The sentence, with three slots

"For [index range], define $A[i]$ to be the [maximum / minimum / number of] [quantity] achievable using only [the restricted resource]. We also set $A[0] = 0$. The final answer is $A[n]$."

The whole skill is choosing what the index restricts. There are only a few options and one of them is always right:

The index meansUse it whenCourse example
the first i items are availableItems are independent and considered in orderShelves, subset sum
a budget or capacity of iThere is a numeric resource being spentBundling apples, shares
the prefix $A[1 \ldots i]$The input is a sequence and the answer is about a prefixDominoes, books
two prefixes $[1 \ldots i]$ and $[1 \ldots j]$Two sequences being comparedEdit distance
the subtree rooted at $v$The input is a treeIndependent set in a tree
an interval $[i \ldots j]$The answer splits at an interior pointOptimal BST
Say what the entry holds, not how it is computed

"$A[i]$ is the maximum dividends achievable with budget $i$" is a definition. "$A[i] = \max\{A[i-1],\, A[i-c] + d\}$" is not, it is part (b) written in the wrong box. Part (a) should be readable by someone who has not seen your recurrence.

Part (b): the Bellman equation

Every Bellman equation in this course comes from the same question: look at an optimal solution to the subproblem, and ask what the last decision was. Enumerate the possible answers, and each one leaves behind a smaller subproblem you have already defined.

The justification, which is most of the marks

"Consider an optimal solution to the subproblem indexed by i. Either it [does X], in which case the rest of it must be an optimal solution to [smaller subproblem], giving value [expression]; or it [does not do X], in which case it is an optimal solution to [other subproblem], giving [expression]. These cases are exhaustive, so the optimum is the better of the two, which is what the recurrence takes."

Two claims are hiding in there and both are needed:

  • Exhaustive. Every optimal solution falls into one of your cases. If it can do something else, your recurrence misses it.
  • Optimal substructure. The leftover piece is itself optimal for the smaller problem. If it were not, you could improve it and improve the whole, contradiction.
Base cases are marked separately

"Make sure to specify the base cases" appears in the question wording every year. Write them on their own line, labelled. Usually $A[0] = 0$, and often a second one such as $A[i] = 0$ for $i < 0$, or $A[m][0] = m$. Missing them costs a mark when you have done the hard part correctly.

Part (c): filling it, animated

This is the December 2024 shares problem. Budget $B$, companies with cost $c_i$ and dividend $d_i$ per share, and you may buy more than one share from the same company. Maximise total dividends within budget.

The array and the recurrence

For $b = 0, 1, \ldots, B$, let $D[b]$ be the maximum total dividends achievable with total cost at most $b$. The answer is $D[B]$.

$$D[0] = 0,$$ $$D[b] \;=\; \max\left\{\; D[b-1], \;\; \max_{\substack{1 \le i \le n \\ c_i \le b}} \bigl( D[b - c_i] + d_i \bigr) \;\right\} \qquad \text{for } b \ge 1 .$$

The $D[b-1]$ term covers "do not spend this last dollar". The inner maximum covers "the last share bought was from company $i$". Because $D[b - c_i]$ is a full solution rather than a company-restricted one, company $i$ can be chosen again, which is exactly what "you can purchase more than one share" requires.

Bottom up fill

One row, filled left to right. Each cell looks back at one cell per company. The arrows show which cells it reads, so you can see that they are all already computed.

Why left to right is the whole of "bottom up"

$D[b]$ reads only cells with a strictly smaller index, since every $c_i \ge 1$. So filling in increasing $b$ guarantees that every cell a formula needs is already written. That single sentence is what part (c) means by "describe the order in which you would compute your table entries", and it is worth stating explicitly.

If the recurrence for a cell ever read a cell with a larger index, the fill order would be wrong and the algorithm would be reading garbage. Checking that is the sanity check for the whole question.

The pseudocode and the running time

Shares(c[1..n], d[1..n], B)
1  D[0] = 0,  J[0] = 0
2  for b = 1 to B
3      D[b] = D[b-1]
4      J[b] = 0                       // 0 means "buy nothing at this budget"
5      for i = 1 to n
6          if c[i] ≤ b and D[b - c[i]] + d[i] > D[b]
7              D[b] = D[b - c[i]] + d[i]
8              J[b] = i               // last share bought was from company i
9  return D[B], J

Running time. The outer loop runs $B$ times, the inner loop $n$ times, and each iteration is $O(1)$, so the fill is $O(nB)$. That is exactly the bound the question demands.

The traceback array

The question asks for "how many shares to buy from each company", not just the best total. The table alone does not tell you that, so you store a second array recording which choice achieved the maximum at each cell, then walk it backwards.

Recover(J, c, B)
1  count[1..n] = 0
2  b = B
3  while b > 0 and J[b] ≠ 0
4      i = J[b]
5      count[i] = count[i] + 1
6      b = b - c[i]
7  while b > 0 and J[b] == 0
8      b = b - 1                      // walk past budgets where nothing was bought
9  return count

The walk visits each budget value at most once, so recovery is $O(B)$ and does not change the overall bound.

This is where the marks leak

Part (c) in December 2024 was worth 7 marks and explicitly said the algorithm "should also compute how many shares to buy from each company". A perfect table fill with no traceback is roughly half the answer. Whenever the question names an output object, add the second array. It costs four lines.

The recurrence that looks fine and is not a recurrence at all

On the shelves problem the most common wrong answer defines S[i] = minimum total height for the first i books, then writes something like "S[i] = S[i-1] if book i fits on the last shelf and is no taller than what is already on it".

That is not a valid recurrence, because S[i-1] is a number. It does not tell you which books are on its last shelf, what their total thickness is, or what their maximum height is, so the condition cannot be evaluated. There may be many optimal solutions to the same subproblem and they disagree about all three of those things.

You could repair it by adding the running thickness and running maximum height as extra parameters, but do not: that makes the array size exponential in the input, so the algorithm stops being polynomial.

The fix is to guess more. Do not guess only where the last book goes, guess the entire last shelf: minimise over j, the index of the first book on it. That is what the worked answer below does, and it is why the answer is O(n2) rather than O(n).

Edit distance, the two dimensional case

Input: strings $X$ of length $m$ and $Y$ of length $n$. Output: the fewest single character insertions, deletions and substitutions turning $X$ into $Y$.

Array, recurrence, base cases

Let $E[i][j]$ be the edit distance between the prefixes $X[1 \ldots i]$ and $Y[1 \ldots j]$. The answer is $E[m][n]$.

$$E[i][0] = i, \qquad E[0][j] = j$$ $$E[i][j] \;=\; \min \begin{cases} E[i-1][j] + 1 & \text{delete } X[i] \\[2pt] E[i][j-1] + 1 & \text{insert } Y[j] \\[2pt] E[i-1][j-1] + \mathbb{1}\{X[i] \ne Y[j]\} & \text{match or substitute} \end{cases}$$

Justification. Look at what an optimal edit sequence does with the last characters. Either it deletes $X[i]$, leaving the problem of turning $X[1 \ldots i-1]$ into $Y[1 \ldots j]$; or it inserts $Y[j]$, leaving $X[1 \ldots i]$ into $Y[1 \ldots j-1]$; or it pairs $X[i]$ with $Y[j]$, costing $1$ if they differ and $0$ if they match, leaving $X[1 \ldots i-1]$ into $Y[1 \ldots j-1]$. There is nothing else a last operation can do, so the cases are exhaustive.

Fill order. Row by row, left to right. Each cell reads only up, left, and up-left, all of which are already written. Running time $O(mn)$, one constant time operation per cell.

The 2D pattern in general

Two sequences being compared always gives a grid where each cell depends on some subset of up, left, up-left. Longest common subsequence, sequence alignment, and edit distance are the same grid with different costs on the three arrows. If you can draw the three arrows, you have the recurrence.

Pseudo-polynomial time, and why O(nB) is not polynomial

This is examinable in its own right. Assignment 4 asked directly why an O(nP) algorithm for a problem you just proved NP-complete does not prove P = NP.

The answer

Polynomial time means polynomial in the number of bits of input. The budget $B$ is one number, written in $\log B$ bits. So an $O(nB)$ algorithm is

$$O(nB) \;=\; O\!\left(n \cdot 2^{\log B}\right),$$

which is exponential in the length of that input, not polynomial. It is called pseudo-polynomial: polynomial in the numeric value of the input, exponential in its size.

Concretely, a $64$ bit budget is $8$ bytes of input and up to $2^{64}$ table columns.

The consequence worth understanding

Subset Sum is NP-complete and also has an $O(nB)$ algorithm, with no contradiction. NP-completeness says there is no algorithm polynomial in the input size. The DP is polynomial in the input value. Both are true, because those are different quantities whenever numbers are written in binary.

The tell is a running time mentioning a numeric input value ($B$, $W$, $P$) instead of only counts of things ($n$, $m$, $k$). Say the words "pseudo-polynomial" if you see one.

Two shapes cover almost all of them

Binary choice on the last item, take it or leave it:

$$A[i] \;=\; \max\bigl\{\, A[i-1], \;\; A[i-w] + v \,\bigr\}$$

Subset sum, dominoes, weighted intervals.

Best over a split point, the last group starts somewhere, or the root is one of the keys:

$$A[i] \;=\; \min_{1 \le j \le i} \bigl(\, A[j-1] + \operatorname{cost}(j, i) \,\bigr)$$

Shelves, bundling, optimal BST. This one has an inner loop, so it costs a factor of $n$ more.

Ask "is the last decision a yes/no, or a where?" and you have picked your shape.

Exam answer, written out

October 2025 Q3. Books $1, \ldots, n$ with thickness $T[i]$ and height $H[i]$, stored on shelves in order, so each shelf holds consecutively numbered books. A shelf holds total thickness at most $L$, and its height becomes the maximum height of the books on it. Minimise the total height of the shelves.

Think about it first, then open this

(a) The array. For $i = 0, 1, \ldots, n$, let $S[i]$ be the minimum total shelf height needed to store books $1, \ldots, i$. Base case $S[0] = 0$. The answer is $S[n]$.

(b) The Bellman equation.

$$S[0] = 0$$ $$S[i] \;=\; \min_{\substack{1 \le j \le i \\[2pt] \sum_{k=j}^{i} T[k] \;\le\; L}} \left(\, S[j-1] \;+\; \max_{j \le k \le i} H[k] \,\right)$$

Justification. In an optimal arrangement of books $1, \ldots, i$, the last shelf holds some block of consecutive books $j, j+1, \ldots, i$. That shelf's height is $\max_{j \le k \le i} H[k]$, and it is legal exactly when $\sum_{k=j}^{i} T[k] \le L$. Whatever is left, books $1, \ldots, j-1$, must itself be arranged at minimum total height, because if it were not we could replace it with a better arrangement and lower the total, contradicting optimality. So the cost is $S[j-1] + \max_{j \le k \le i} H[k]$. The value of $j$ is not known, but it must be one of $1, \ldots, i$, so taking the minimum over all feasible $j$ is exhaustive and correct.

(c) Bottom up. Compute in the order i = 1, 2, ..., n. For each i, run the inner loop j = i down to 1, accumulating the running thickness and running max height so both are available in O(1) per step.

DP-TotalHeight(T, H, L)
1  S[0] = 0
2  for i = 1 to n
3      S[i] = ∞
4      thick = 0
5      maxh = -∞
6      for j = i downto 1
7          thick = thick + T[j]
8          maxh = max(maxh, H[j])
9          if thick > L
10             break                          // no smaller j can fit either
11         if S[j-1] + maxh < S[i]
12             S[i] = S[j-1] + maxh
13             J[i] = j                       // first book on the last shelf
14 return S[n], J

Why descending $j$. Going down from $i$, adding one book at a time, lets both the thickness sum and the height maximum be updated in constant time. Going up would need a fresh scan for each $j$ and cost a factor of $n$ more.

Running time. Two nested loops of at most $n$ iterations each, constant work inside, so $O(n^{2})$.

(d) Recovering the shelves. J[i] stores the j that achieved the minimum for S[i], that is, the first book on the last shelf of the optimal arrangement of 1..i. Walk it backwards:

1  t = n
2  while t ≥ 1
3      s = J[t]
4      output shelf holding books s, s+1, ..., t
5      t = s - 1

This outputs the shelves right to left, so reverse the list if order matters. Each iteration consumes at least one book, so it is $O(n)$.

The move to notice

The last shelf is a contiguous block ending at $i$, and you do not know where it starts, so you minimise over the start point. That is the "best over a split" shape, and it is why this is $O(n^{2})$ rather than $O(n)$. The greedy version of this problem is O(n), and the thing that broke greedy is the height: cramming one more book onto a shelf can raise that shelf's height by more than it saves later.

Recognising Q2 in 60 seconds
  • Stated running time mentions a product: $O(nB)$, $O(nk)$, $O(n^{2})$, $O(mn)$. That is a table with those dimensions and it names your array for you.
  • The problem asks for a maximum or minimum over choices, with choices interacting through a shared resource.
  • Ask what the last decision was, and enumerate every value it could take.
  • Check every term on the right of your recurrence has a smaller index than the left. If not, your fill order does not exist and the recurrence is wrong.
