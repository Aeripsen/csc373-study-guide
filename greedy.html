Interval scheduling

Input: intervals $I_{j} = [s_{j}, f_{j}]$. Output: the largest set of pairwise disjoint intervals.

There is a DP solution. Sort by finish time, let c[j] be the best you can do using only $I_{1}..I_{j}$, and let $p[j] = max{k < j : f_{k} < s_{j}}$, the last interval that does not clash with j. Then c[j] = max{c[j-1], c[p[j]] + 1}. It works and it is O(n log n).

But you never need the table. Sort by finish time and take greedily.

Earliest finish time first

Sorted by right endpoint. Take the first interval that does not clash with what you already have, and skip the rest.

Eight intervals, sorted by finish time. Press Step.
GreedySchedule(I)
1  Sort I so that f₁ ≤ f₂ ≤ ... ≤ fₙ
2  T = ∅,  f* = -∞
3  for j = 1 to n
4      if sj > f*
5          add Ij to T
6          f* = fj
7  return T

Running time. O(n log n) for the sort, then one O(n) pass. If the input is given sorted, O(n). The exam usually says "you can assume the input is sorted", which is the marker telling you the target is O(n) and that you should say so.

Why earliest finish time

Every interval you take costs you the same thing, one slot, and buys you the same thing, one point of value. So the only way to compare two candidates is by what they leave behind. Finishing earliest leaves the most room, and room is the only resource. That is the whole argument, and it is also exactly the sentence that makes the exchange step in the proof work.

Three rules that look fine and are not

Knowing why the wrong rules fail is how you avoid inventing one under exam pressure. Each of these is beaten by a small counterexample.

If you invent a greedy rule on the exam, attack it first

Spend 90 seconds trying to break your own rule with three or four intervals before you write the proof. The failure modes above are the standard ones: something that starts early and runs long, something short that straddles two others, something that looks locally safe but blocks a chain. If you cannot break it in 90 seconds, commit and write the proof.

The exchange argument

This is the load bearing idea of the whole unit, and it is worth roughly 8 to 10 of the 15 marks on the exam question.

You want to prove greedy is optimal. You cannot compare it to "the" optimal solution directly, because there may be many and you do not know which one. So you prove something slightly different and much easier: at every step, greedy's partial answer is compatible with optimality, meaning some optimal solution contains it.

Swapping greedy's choice into an optimal solution

Greedy picks Ij. Suppose an optimal O does not contain it. We build a different optimal solution that does.

What the exchange is really doing

It never claims greedy's choice is better than O's. It claims it is no worse: you can swap it in without breaking anything and without losing count. That is a far weaker claim, which is why it is provable.

The swap survives because greedy picked the earliest finishing interval, so $f_{j} \le f_{k}$. Anything in O that fitted after $I_{k}$ still fits after $I_{j}$. The greedy rule is exactly the hypothesis the exchange needs, which is not a coincidence: you choose the greedy rule so that the exchange will work.

The proof template, in full

Learn this by heart, it is worth 10 marks a year

Lemma. For every $j \in {0, 1, ..., n}$, let $T_{j}$ be the algorithm's partial solution after processing item j. Then $T_{j} \subseteq O$ for some optimal solution O.

Proof, by induction on j.

Base case. $T_{0} = \emptyset$, which is contained in every optimal solution.

Inductive step. Suppose $T_{j-1} \subseteq O$ for an optimal O. Three cases.

  1. Greedy skips item j. Then $T_{j} = T_{j-1} \subseteq O$. Done.
  2. Greedy takes j and $I_{j} \in O$. Then $T_{j} = T_{j-1} \cup {I_{j}} \subseteq O$. Done.
  3. Greedy takes j and $I_{j} \notin O$. Since $T_{j-1} \cup {I_{j}}$ is feasible but O does not contain $I_{j}$, there is some $I_{k} \in O \setminus T_{j-1}$ that conflicts with $I_{j}$. Take the smallest such k. Let $O' = (O \setminus {I_{k}}) \cup {I_{j}}$.
    • O' is feasible, because $f_{j} \le f_{k}$ by the greedy rule, so anything in O compatible with $I_{k}$ is compatible with $I_{j}$.
    • O' is optimal, because |O'| = |O|.
    • Tj ⊆ O', because $T_{j-1} \subseteq O$, the removed $I_{k}$ was not in $T_{j-1}$, and $I_{j}$ was added.

Conclusion. So $T = T_{n} \subseteq O$ for some optimal O. It cannot be a strict subset: every interval not in T was rejected because it conflicts with something in T, so it cannot appear in any feasible set containing T. Hence T = O and greedy is optimal.

The ending people forget

"Greedy's answer is contained in an optimal solution" is not the same as "greedy's answer is optimal". The empty set is contained in an optimal solution too. You must finish with the argument that T cannot be extended, so it equals O rather than sitting strictly inside it. It is two sentences and it is worth marks. Do not stop one line early.

The wrong induction, and the counterexample that kills it

The proof obligation is exactly this: every partial solution the greedy algorithm computes can be extended to some optimal solution. You are not showing that every optimal solution matches the greedy one, which is usually false.

The tempting alternative is to induct differently: "greedy's answer after the first i items is an optimal solution for the first i items". That statement is often true, but the usual proof of it is broken. It quietly assumes that removing item i from an optimal solution for i items leaves an optimal solution for i-1 items, and that is false.

Take the shelves problem with shelf length 10 and books of thickness 5, 2, 2, 5. One optimal solution uses two shelves: the first book alone, then the last three together (2 + 2 + 5 = 9). Now delete the last book from that solution. You are left with the first book alone and then 2 + 2, still two shelves, but the optimum for 5, 2, 2 is one shelf, since 5 + 2 + 2 = 9 fits. So the leftover is not optimal for the subproblem and the induction hypothesis does not apply.

If you want this style of argument to work, remove the whole last shelf, not the last item. Safer still, use the contained-in-an-optimal-solution template above, which has no such hole.

The other accepted shape: induction on input size

Some problems read more naturally as: greedy's first choice matches some optimal solution, the rest of the input is a smaller instance of the same problem, so apply the induction hypothesis to it. The 2025 midterm's couples-in-a-line question and the 2024 final's post office question both work best this way. Say in your first line which induction you are doing and on what quantity.

Minimising lateness

Input: tasks with duration $t_{i}$ and deadline $d_{i}$. You choose start times, no overlaps, no idle time needed. Output: a schedule minimising the maximum lateness $max_{i} max{0, f_{i} - d_{i}}$.

The rule

Earliest deadline first. Sort by $d_{i}$ ascending and run tasks back to back in that order. Durations are irrelevant to the ordering, which is the surprising part.

Why durations do not matter

Total time used is the same in every schedule, since all tasks run and there is no idle time. So ordering does not change when the work ends, only who is late. Given that, you want the most urgent things earliest, and urgency is the deadline alone.

The proof is a swap argument on adjacent inversions: if a task with a later deadline runs immediately before one with an earlier deadline, swapping them does not increase the max lateness. Any schedule can be turned into the earliest deadline order by repeatedly fixing adjacent inversions, none of which makes things worse, so the sorted schedule is at least as good as any schedule.

Greedy or DP, deciding in 30 seconds

On the exam the question is titled, so you are told which. In practice, and for understanding, the distinction is this:

GreedyDynamic programming
Decision at each stepCommitted, never revisitedBoth options explored, best kept
Subproblems solvedOne per stepAll of them, tabulated
Typical running timeO(n) or O(n log n)O(n2), O(nB), O(nk)
Proof burdenExchange argument, hardCase exhaustiveness, easy
Fails whenLocal choice can be regretted laterAlmost never, just slower
The tell is in the stated running time

If the question demands O(n) or O(n log n), a table is out of reach and it must be greedy. If it says O(nB) or O(n2), that is a table shape and it is DP. The October 2025 midterm asked the same books-and-shelves problem twice: greedy when shelves were identical, DP when shelves had adjustable heights. What changed is that with heights, fitting one more book on a shelf can raise its height and cost you more than it saves. The moment a local choice has a delayed cost, greedy dies and you need a table.

Exam answer, written out

December 2024 Q3. Houses at sorted positions $x_{1} \le ... \le x_{n}$ on the road [0, 100]. Every house needs a post office within 2 km. Minimise the number of post offices. Full credit requires O(n), and the question explicitly demands an inductive proof that each partial solution extends to an optimal one.

Think about it first, then open this

Algorithm. Scan left to right. Take the leftmost house not yet covered, at position x, and put a post office at x + 2. Remove every house it covers, that is, every house at position at most x + 4. Repeat.

PostOffices(x[1..n])
1  k = 0,  i = 1
2  while i ≤ n
3      k = k + 1
4      y[k] = x[i] + 2
5      while i ≤ n and x[i] ≤ y[k] + 2
6          i = i + 1
7  return k, y[1..k]

Running time. The index i only ever increases and never exceeds n, so the two loops together perform O(n) iterations of constant work. The input is given sorted, so no sorting is needed and the total is O(n).

Correctness (every house is covered). The outer loop only ends when i > n, and the inner loop advances past house i only once a post office covering it has been placed. So on exit, every house is within 2 km of some post office.

Optimality. We prove by induction on k that for every k, the first k post offices placed by the algorithm are the first k post offices of some optimal solution, when both are listed left to right.

Base case. k = 0 is trivial: the empty partial solution agrees with every optimal solution.

Inductive step. Suppose the algorithm's first k-1 offices agree with an optimal solution O. Both therefore cover exactly the same set of houses, namely a prefix $x_{1}, ..., x_{i-1}$, so house $x_{i}$ is the leftmost house uncovered in both. O must cover $x_{i}$ with some office at a position $y \in [x_{i} - 2, x_{i} + 2]$, and since the houses are sorted, that is O's k-th office. The algorithm puts its k-th office at $y' = x_{i} + 2 \ge y$.

Form O' from O by moving that one office from y to y'. Every house O's k-th office covered lies in [y - 2, y + 2]. Any such house at position at least $x_{i}$ lies in $[x_{i}, y + 2] \subseteq [y' - 2, y' + 2]$ and so is still covered, using $y' \ge y$ and $y' - 2 = x_{i}$. Any such house below $x_{i}$ is already covered by the first k-1 offices, since $x_{i}$ is the leftmost uncovered house. So O' covers every house that O covered, uses the same number of offices, and is therefore also optimal. Its first k offices agree with the algorithm's, completing the step.

Conclusion. Taking k to be the number of offices the algorithm places, its full solution is the prefix of some optimal solution. Since it already covers every house, that optimal solution has no further offices, so the two are equal and the algorithm is optimal.

The one idea, in one sentence

Push each office as far right as it can go while still covering the leftmost uncovered house. That maximises what it reaches without giving anything up, which is exactly the property the exchange step needs. Almost every "cover a line with intervals" greedy has this shape, so recognise it and reuse it.

Recognising Q3 in 60 seconds
  • Target running time is O(n) or O(n log n). Too fast for a table.
  • The output is a set or a partition built one piece at a time, and every piece is worth the same.
  • The candidate rules are: earliest finish, earliest deadline, largest ratio, or "push as far as feasible". Try them against a four element counterexample before committing.
  • Write the algorithm and running time in five minutes, then spend the rest on the induction. The proof is where the marks live.
