NP, via certificates and certifiers

A decision problem has a yes or no answer. X is in NP if there is a polynomial time algorithm B (the certifier) and a polynomial p, such that for every input x:

$$x \text{ is a Yes instance} \quad \Longleftrightarrow \quad \exists\, y \ \text{ with } \ |y| \le p(|x|) \ \text{ and } \ B(x, y) = \text{Yes}$$

That y is the certificate. Informally: a Yes answer has a short proof that can be checked quickly. Nothing is claimed about finding it.

The two sentences that answer this part, every time

"The certificate is [the object the question asks whether one exists]. The certifier checks that [it has the required size] and that [it satisfies the defining property], which takes polynomial time."

The certificate is always the thing after "decide if there is a ...". You are not required to be clever, and being clever here loses time.

Why "exactly k edges" appears in the spanning tree row

A graph on $|V|$ vertices that is connected and has $|V| - 1$ edges is necessarily acyclic, so those two checks together certify "tree" without a separate cycle hunt. Small facts like this are what makes a certifier obviously polynomial.

A problem that is not obviously in NP

No Long Path: given a directed graph G and an integer k, decide whether every simple path in G has at most k edges.

Why the certificate approach fails here

A Yes instance is one where all paths are short. To convince someone of that, you would have to account for every simple path, and there can be exponentially many. There is no obvious short object that proves a universal statement.

The pattern: NP is good at existence claims ("there is a set", "there is an assignment") and bad at universal ones ("every path", "no subset"). Negating an NP problem generally lands you in co-NP, and whether NP equals co-NP is open. If an exam problem is phrased with "every" or "no", check whether it can be rewritten as an existence claim before assuming it is in NP.

Reductions, and the direction

$X$ is polynomial time reducible to $Y$, written $X \le_{P} Y$, if there is a polynomial time algorithm $R$ turning any instance $x$ of $X$ into an instance $R(x)$ of $Y$ such that

$$x \text{ is a Yes instance of } X \quad \Longleftrightarrow \quad R(x) \text{ is a Yes instance of } Y$$

Read it as "$X$ is no harder than $Y$", because a solver for $Y$ gives you a solver for $X$.

The arrow, and what happens when you reverse it

You are proving a new problem Y is hard. Switch the direction and watch the argument collapse.

The single most common exam error in this course

To prove your problem $Y$ is NP hard, you reduce a known NP complete problem $X$ into it:   $X \le_{P} Y$.   The known hard problem is the source. Your new problem is the target.

Sanity check before you write anything: your reduction should take an instance of Vertex-Cover (or whichever you chose) as input, and produce an instance of the exam's problem as output. If it is the other way round, you have proved the useless direction.

The lemma that makes reductions worth anything

If $X \le_{P} Y$ and $Y \in \mathrm{P}$, then $X \in \mathrm{P}$.

Proof. Let $R$ be the reduction, running in time $O(n^{d})$, and let $A$ be a polynomial time algorithm for $Y$. Then $A(R(x))$ decides $X$. It is correct because $R$ preserves Yes and No. It is polynomial because $R$ takes $O(n^{d})$, and the output of $R$ has size at most $O(n^{d})$, since an algorithm cannot write more than it has time for. So $A$ runs on an input of polynomial size and therefore in polynomial time.

That bracketed step is the one people skip. Without it the composition might not be polynomial.

$\mathrm{P} \subseteq \mathrm{NP}$. If $A$ solves $X$ in polynomial time, use a certifier that ignores the certificate entirely and just runs $A$. That is the whole proof.

If one NP complete problem is in P, then $\mathrm{P} = \mathrm{NP}$. Every problem in NP reduces to it, and reductions preserve membership in P.

Cook and Levin, 1971 and 1973

NP complete problems exist. In particular Circuit-SAT and 3-SAT are NP complete.

This is the bootstrap. Every later NP completeness proof is a reduction chain back to SAT, so you never have to argue about "every problem in NP" yourself. Karp added 21 more in 1972, and there are now thousands.

A boolean circuit, since Circuit-SAT is defined by one

A directed acyclic graph where the sources are labelled by constants 0 or 1 or by distinct variables, every other node is labelled AND, OR or NOT, and there is a single sink giving the output. Circuit-SAT asks whether some assignment to the variables makes the output 1.

Which source problems are fair game

Course staff have confirmed you only need the NP complete problems covered in class: 3-SAT and the problems reduced from it in lectures, namely subset sum, independent set, vertex cover, set cover, 3-colouring and binary integer linear programming. Any of those may be used as the source of your reduction.

The practical advice that came with it: 3-SAT works in most cases. If you cannot see a match to a more specific problem within a couple of minutes, build a 3-SAT reduction, because a clause-and-literal gadget can encode almost anything.

Match the shape, not the story

The exam dresses these up as students, clubs, jobs and roads. Strip the story and ask what the combinatorial object is. "Every club must contain a representative and there are at most k representatives" is a covering problem where the clubs are the things to cover, which is Set-Cover, or Vertex-Cover when every club has exactly two members.

The exam hint usually names the shape outright. December 2024 said "this is a type of covering problem", which is the paper telling you which row of that table to use.

Independent set, vertex cover, clique: one graph, three problems

These three are the same question asked in three ways, and the relationship between them is the cheapest reduction in the course.

One graph, three readings

S is independent exactly when V \ S is a vertex cover, and exactly when S is a clique in the complement graph. Toggle the view.

The identity, worth memorising
$$S \text{ is an independent set in } G \quad \Longleftrightarrow \quad V \setminus S \text{ is a vertex cover of } G$$

Proof, both ways at once. S is independent means no edge has both endpoints in S, which means every edge has at least one endpoint outside S, which means every edge is covered by V \ S. Each step is a restatement, so it reads in either direction.

Immediately: $G$ has an independent set of size $\ge k$ exactly when it has a vertex cover of size $\le n - k$. That is a reduction in one line, in both directions.

Exam answer, written out

December 2024 Q7. Students s₁, ..., sm, clubs c₁, ..., cn, with Ci the members of club i. Decide if there is a set R of at most k students such that every club contains at least one member of R. Prove this problem, called Representatives, is NP complete.

Try it, then open this

Part 1: Representatives is in NP.

The certificate is the set $R \subseteq \{s_1, \ldots, s_m\}$. The certifier checks that $|R| \le k$, and that for each club $c_i$ the set $C_i \cap R$ is non empty. The first check takes $O(m)$ time and the second takes $O\!\left(\sum_i |C_i|\right)$, both polynomial in the input size. So Representatives is in NP.

Part 2: Representatives is NP hard.

We show $\text{Vertex-Cover} \le_{P} \text{Representatives}$. Since Vertex-Cover is NP complete, this makes Representatives NP hard.

The reduction. Given an instance (G = (V, E), k) of Vertex-Cover, construct an instance of Representatives as follows:

  • for each vertex $u \in V$, create a student $s_u$;
  • for each edge $(u,v) \in E$, create a club with membership set $C_{(u,v)} = \{s_u,\, s_v\}$;
  • keep the same bound $k$.

This writes $|V|$ students and $|E|$ clubs of two members each, so it runs in $O(|V| + |E|)$ time, which is polynomial.

Correctness, forward direction. Suppose $G$ has a vertex cover $S$ with $|S| \le k$. Let $R = \{s_u : u \in S\}$, so $|R| = |S| \le k$. Take any club $C_{(u,v)}$. Since $S$ covers the edge $(u,v)$, at least one of $u, v$ lies in $S$, so at least one of $s_u, s_v$ lies in $R$. Hence every club contains a representative and $R$ is a Yes certificate for the constructed instance.

Correctness, reverse direction. Suppose the constructed instance has a valid set $R$ with $|R| \le k$. Let $S = \{u : s_u \in R\}$, so $|S| = |R| \le k$. Take any edge $(u,v) \in E$. The club $C_{(u,v)} = \{s_u, s_v\}$ contains a member of $R$, which must be $s_u$ or $s_v$, so $u$ or $v$ lies in $S$. Hence every edge is covered and $S$ is a vertex cover of size at most $k$.

The two directions give: $(G,k)$ is a Yes instance of Vertex-Cover exactly when its image is a Yes instance of Representatives. So the reduction is correct.

Conclusion. Representatives is in NP and is NP hard, therefore Representatives is NP complete.

Why Vertex-Cover and not Set-Cover

Either works. Set-Cover is the more natural fit, since a club is an arbitrary set of students and Set-Cover allows arbitrary sets. But Vertex-Cover is a special case where every set has size two, and reducing from a special case is still a valid proof and produces a simpler construction. Pick whichever gives you the shorter reduction, and reducing from the more restricted problem usually does.

Reducing from a special case is fine, because the special case is itself NP complete. Reducing to a special case is where you have to be careful, since your construction has to land inside the restriction.

Q7 in six lines
  1. Name the certificate and the certifier. Two sentences, three minutes, worth about 3 marks.
  2. Name your source problem and state the direction: $X \le_{P} Y$.
  3. Give the construction as a bulleted mapping, and say it is polynomial time.
  4. Forward direction: a Yes for X builds a Yes for Y.
  5. Reverse direction: a Yes for Y builds a Yes for X.
  6. Write the closing sentence: "in NP and NP hard, therefore NP complete".
The follow up question they like to attach

"You have a pseudo-polynomial algorithm for this problem. Why does that not prove P = NP?"

Because polynomial time means polynomial in the number of bits of input. An $O(nP)$ algorithm, where $P$ is a sum of input numbers, is exponential in the length of those numbers, since $P$ written in binary takes only $\log P$ bits. See the DP page for the full version of this.
